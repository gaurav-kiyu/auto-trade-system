# OPB v2.60 — SCRATCH FORENSIC TOOLING QUARANTINE ARCHIVE

**Governance:** `OPB-FINAL-PHASE-GOVERNANCE-001`  
**RFC:** `RFC-OPB-V260-LIFECYCLE-001 (CORRECTED FINAL GATE)`  
**Quarantine Date:** 2026-10-05  

## Incident Summary
During forensic analysis on 2026-10-05, it was discovered that legacy scratch verification scripts (`scratch/verify_all_signals_cross_surface.py` and `scratch/audit_cross_surface.py`) directly called:
```python
SignalTracker.get_instance(db_path="db/signals_history.db")
```
Because `SignalTracker._init_db()` executes backward-compatible `ALTER TABLE` DDL migrations upon connection instantiation, executing these scripts against `db/signals_history.db` triggered automatic column additions on `system_signals` (`exit_reason`, `exit_price`, `exit_at`), which updated SQLite schema metadata and altered the file SHA-256.

## Quarantined Unsafe Artifacts
- `HISTORICAL_UNSAFE_verify_all_signals_cross_surface.py`: Original script that instantiated write-capable `SignalTracker` against production DB path.
- `HISTORICAL_UNSAFE_audit_cross_surface.py`: Original script that instantiated write-capable `SignalTracker` against production DB path.

## Remediation Standard
Under OPB-FINAL-PHASE-GOVERNANCE-001:
1. No read-only audit or verification script may open `db/signals_history.db` in write-capable mode.
2. Direct SQLite queries must use explicit read-only immutable URIs (`file:...signals_history.db?mode=ro&immutable=1`).
3. APIs requiring physical file instances of `SignalTracker` must operate on an isolated temporary sandbox copy generated by `core.signals.audit_db_safety.create_isolated_audit_db_copy()`.
