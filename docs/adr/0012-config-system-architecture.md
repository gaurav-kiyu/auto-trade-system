# ADR 0012: Configuration System Architecture — Three-Layer Merge with Secure Secrets

## Status

Accepted (2026-07-18)

## Date

2026-07-18

## Context

The trading bot requires hundreds of configuration parameters (974+ keys across index and stock configs)
controlling risk limits, execution modes, signal thresholds, broker connections, ML parameters, and more.
These parameters come from multiple sources with different trust levels:

1. **Safe defaults** shipped with the codebase
2. **User config** customized for each deployment environment
3. **Local overrides** for development/testing
4. **Environment variables** for CI/CD, Docker, and secrets management
5. **Secrets** (API keys, tokens) that must never be stored in plaintext

A robust config system was needed to:
- Merge configs from multiple layers with clear precedence
- Validate types and required keys at startup
- Handle secrets securely (env vars, not plaintext files)
- Detect configuration drift between versions
- Audit config changes for compliance
- Freeze config at runtime to prevent accidental mutation

## Decision

### Architecture Overview

Three-layer merge with environment variable overrides and secure secret handling:

```
Layer 1: json/index_config.defaults.json
             ↓ (merge)
Layer 2: json/config.json
             ↓ (merge)
Layer 3: json/config.local.json
             ↓ (override)
Environment: OPBUYING_* env vars
             ↓ (decrypt)
Secrets: CredentialStorage (env-based)
             ↓ (freeze)
Final: Immutable MappingProxyType
```

### Layer Definitions

| Layer | File | Priority | Purpose |
|-------|------|----------|---------|
| **Defaults** | `json/index_config.defaults.json` | Lowest (base) | Single source of truth for all default values. Every config key MUST have a safe default here. |
| **User Config** | `json/config.json` | Medium | Environment-specific overrides (production, staging, paper). Should NOT contain secrets. |
| **Local Overlay** | `json/config.local.json` | Higher | Developer-specific overrides. Gitignored. |
| **Environment Vars** | `OPBUYING_*` | Highest | Override any key at runtime. For CI/CD, Docker, and secrets. |

### Key Components

#### 1. `core/config_bootstrap.py` — Orchestration
- `get_effective_config()` — The authoritative pipeline entry point
- `initialize_secure_config()` — Initializes `SecureConfig` with project-root defaults
- Performs config drift detection between defaults and merged config
- Freezes the final config to prevent runtime mutation

#### 2. `infrastructure/config/secure_config.py` — Core Engine
- `SecureConfig` class handles multi-layer merge, type coercion, and secure retrieval
- `get_secret()` — Audited access to sensitive values (logged for compliance)
- Redacts secrets in log output automatically
- Fallback to environment variables for all secret values

#### 3. `core/config_engine.py` — Validation
- `ConfigValidator` — Validates types, required keys, and value ranges
- `validate()` — Returns errors/warnings list
- Run during startup; raises `RuntimeError` on validation failure
- Bypassable via `OPBUYING_SKIP_CONFIG_VALIDATION=1` (emergency only)

#### 4. `schemas/` — JSON Schema
- `schemas/index_config.schema.json` — Auto-generated from defaults
- `schemas/stock_config.schema.json` — Auto-generated for stock config
- Generated by `scripts/generate_config_schemas.py`
- Validated by `scripts/validate_config_schema.py`

### Config Drift Detection

On every startup, the config system compares:
- **Missing keys**: Keys in defaults but not in merged config → WARNING (new features with safe defaults)
- **Extra keys**: Keys in merged config but not in defaults → WARNING/CRITICAL (deprecated/removed keys)
- **Risk classification**: CRITICAL keys (MAX_DAILY_LOSS, MAX_DRAWDOWN, etc.) trigger CRITICAL-level logging

### Config Change Audit

- **Audit trail**: All config changes written to `json/config_audit.jsonl` via `write_config_changes_jsonl()`
- **Structure**: `ConfigChange` dataclass with key, old_value, new_value, timestamp, changed_by, risk_level
- **Risk levels**: CRITICAL → high-risk keys, HIGH → moderate risk, NORMAL → safe changes
- **Rollback**: Automatic `.backup.*` files created before every config write

### Secure Secret Handling

- **Never in json/config.json**: Secrets stored in environment variables with `OPBUYING_` prefix
- **Placeholder convention**: `__OPBUYING_BOT_TOKEN_ENV__` in json/config.template.json
- **Redaction**: Secrets redacted in logs and error messages automatically
- **Audited access**: `get_secret()` method logs every access for compliance
- **Credential types**: BOT_TOKEN, CHAT_ID, BROKER_API_KEY, BROKER_ACCESS_TOKEN, AI_ENGINE_API_KEY

### Runtime Freezing

The final config is frozen using `types.MappingProxyType` (recursive):
- Prevents runtime mutation by any module
- Forced mutation attempts raise `TypeError`
- Config hot-reload creates a new frozen copy, not mutation of existing

### Key Constants

| Constant | Purpose |
|----------|---------|
| `CRITICAL_CONFIG_KEYS` | Risk/loss/execution parameters that halt trading if changed |
| `HIGH_RISK_CONFIG_KEYS` | Sizing/timing parameters that affect P&L significantly |
| `_SECRET_SUBSTRINGS` | Key name patterns that trigger redaction |

### Config Precedence Diagram

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────────┐
│  Defaults JSON  │ ──→ │  json/config.json     │ ──→ │  json/config.local.json  │
│ (lowest basis)  │     │ (env overrides)  │     │ (dev overrides)     │
└─────────────────┘     └─────────────────┘     └──────────┬──────────┘
                                                            ↓
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────────┐
│  CredentialStore │ ←── │  OPBUYING_* Env  │ ──→ │  Merged Config     │
│  (secrets only)  │     │  (highest prio)  │     │  → Freeze → Use    │
└─────────────────┘     └─────────────────┘     └─────────────────────┘
```

## Consequences

### Positive
- **Clear precedence**: Always predictable which value wins
- **Security**: Secrets never in version control
- **Validation**: Startup fails fast on config errors
- **Drift detection**: Missing/extra keys logged on every startup
- **Audit trail**: All changes trackable for compliance
- **Runtime safety**: Frozen config prevents accidental mutation

### Negative
- **Complexity**: 974+ keys make the config surface large (mitigated by 16-category key index)
- **Cold start**: Requires `json/config.json` in project root — Documented in setup guides
- **Validation overhead**: Full validation adds ~500ms to startup time
- **Secret indirection**: New developers may be confused by `__OPBUYING_*_ENV__` placeholders

### Neutral
- **Backward compatibility**: Legacy `merge_bot_config()` function retained for existing callers
- **Three layers**: May be overkill for simple deployments (local config can be minimal)
