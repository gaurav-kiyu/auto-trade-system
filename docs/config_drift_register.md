## Drift Categories

| Category | Description | Detection Method |
|----------|-------------|-----------------|
| **KEY_MISSING** | Key exists in defaults but not in env.example or CI config | Automated diff |
| **VALUE_MISMATCH** | Same key has different default values across files | Automated diff |
| **TYPE_MISMATCH** | Same key has different expected types | Schema validation |
| **ORPHANED_KEY** | Key exists in config but not in defaults/schema | Automated scan |
| **STALE_VARIABLE** | Env var referenced in CI/Docker but removed from codebase | Cross-reference scan |
| **DOCUMENTED_WRONG** | Documentation describes different behavior than config | Manual review |
| **DECORATIVE_KEY** | Config key exists (has a declared default) but no live, non-test code path reads it — a Super Admin changing it via UI/config has zero effect | Manual code trace (grep + read the reader, verify the reader is reachable from a real entry point) |
| **HARDCODED_BYPASS** | Live code uses a bare Python literal for a value that also exists as a config key of the same name, so the config key is ignored | Manual code trace |
| **FALLBACK_MISMATCH** | A `.get(key, fallback)` call's fallback literal disagrees with the key's own declared default in `index_config.defaults.json` — harmless while the key is present, a silent behavior change if it's ever omitted | Manual code trace |

Real audit methodology (used for every entry below, not assumed): grep every plausible key name across `core/`, `index_app/`, `scripts/`; read the actual reader function; confirm the reader is reachable from a real, live entry point (`index_app/index_trader.py`'s DI wiring, not just a test file). "No live reader found" is stated only after a repo-wide grep came back empty outside tests/docs.

## Remediation Policy

1. **Detection**: Automated via `scripts/sync_artifacts.py --check-config-drift` and CI pipeline, supplemented by manual real-code-path tracing for the DECORATIVE_KEY/HARDCODED_BYPASS/FALLBACK_MISMATCH categories (automated diffs alone cannot detect "this key exists but nothing reads it" — that requires reading the reader).
2. **Alignment**: Update env.example, CI configs, and documentation to match defaults.
3. **Validation**: Run `scripts/validate_config_schema.py --all` and `scripts/generate_config_schemas.py --check` to verify; run the full test suite after any default-value change.
4. **Prevention**: All new config keys must be added to defaults first, then synced — and whoever adds a config key should grep for (or add) the actual reader in the same change, so a DECORATIVE_KEY entry never gets created going forward.
